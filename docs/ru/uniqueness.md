# Подсчёт уникальности

## Включение

Настройка находится в **Campaign settings → Misc → Uniqueness counting**. Пока она выключена, YellowTDS не рассчитывает уникальность, не создаёт cookie `userid`, а фильтр **Uniqueness** не показывается в flows.

После включения задайте:

- **Method** — идентификатор посетителя;
- **TTL (hours)** — скользящее окно от 1 до 720 часов;
- **GET parameter** — имя параметра, если выбран метод GET.

![Настройки подсчёта уникальности](../assets/screenshots/campaign-settings-uniqueness.png)

Для каждого успешно записанного flow-клика одновременно рассчитываются два признака:

- **Campaign unique** — не было совпадающего клика в этой кампании за TTL;
- **Flow unique** — не было совпадающего клика в выбранном flow за TTL.

Расчёт выполняется даже тогда, когда в flows нет фильтров уникальности. Safe Page, JS-проверка до входа в flow, trafficback, запрос без выбранного flow и откатившаяся запись в расчёт не попадают.

## Методы

| Method | Как проверяется посетитель |
|---|---|
| IP | нормализованный IP |
| IP + UserAgent | нормализованный IP и полный UserAgent |
| Cookie | cookie `userid` |
| Cookie / IP | cookie при наличии, иначе IP |
| Cookie / IP + UserAgent | cookie при наличии, иначе IP и полный UserAgent |
| GET parameter | каноническое значение выбранного GET-параметра |

В комбинированных cookie-методах fallback-хеш записывается всегда. Если cookie пришла, проверяется только `userid`. Если cookie потеряна, следующий запрос проверяется по fallback.

Cookie `userid` создаётся только для трёх cookie-методов, живёт 30 дней и продлевается после записанного клика. Она host-only, `HttpOnly`, `SameSite=Lax`; на HTTPS также устанавливается `Secure`. В остальных методах `{userid}` возвращает пустую строку.

GET-метод различает строки и массивы. Порядок элементов списка сохраняется, ключи ассоциативных и вложенных массивов сортируются. Пустая строка и пустой массив являются значениями и участвуют в хеше. Если параметр отсутствует, клик считается Campaign unique и Flow unique, а идентификатор для него не записывается.

## Скользящий TTL

Каждый записанный flow-клик становится новым последним визитом, в том числе non-unique. Совпадение учитывается только при `click time > now - TTL`. Поэтому клик ровно на границе TTL уже считается unique.

Пример с TTL 24 часа: повтор через 20 часов будет non-unique и передвинет окно ещё на 24 часа от нового клика.

## Фильтр в flows

После включения в flow filters появляется **Uniqueness**:

- operator: **is unique** или **is not unique**;
- value: **Campaign** или **Flow**.

Flows по-прежнему проверяются сверху вниз, и выбирается первый совпавший. Фильтр уникальности отсутствует в Safe Page.

Нельзя выключить подсчёт, пока хотя бы в одном flow осталось правило **Uniqueness**. Интерфейс перечислит затронутые flows; сервер повторно проверит это условие при сохранении.

## Статистика

- **Uniques** — сумма Campaign unique;
- **Flow uniques** — сумма уникальных входов по flows, её можно вывести без Group by Flow;
- **U/C**, **EPuC** и **CPuC** используют Campaign uniques.

Старые клики не пересчитываются. Если группа состоит из старых кликов без рассчитанной уникальности или смешивает их с новыми, показатели уникальности выводятся как `—`.
