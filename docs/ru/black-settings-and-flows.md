# Black settings и flows

## Что здесь настраивается

Black branch — это логика для разрешённого трафика.

Основные элементы:

- JS Connect action
- JS bot detection
- flows

## JS bot detection

Поддерживаются:

- events
- timeout
- timezone checks

Это дополнительный этап проверки уже на стороне браузера.

## Flows

Flow — это отдельный маршрут трафика в black branch.

Flow включает:

- name
- filters
- steps
- distribution
- optimization settings

Порядок flows задаёт порядок проверки трафика. Чтобы изменить его, перетащите flow за ручку слева от названия. Когда ручка в фокусе, порядок также можно менять клавишами `↑` и `↓`.

При включённом [подсчёте уникальности](uniqueness.md) в filters доступно условие **Uniqueness** с областями Campaign и Flow. В Safe Page этого фильтра нет.

Фильтр **Bot** использует серверное распознавание User-Agent из DeviceDetector и позволяет выбрать **Yes** или **No**. Он работает до браузерной проверки и не заменяет отдельный этап **JS bot detection**. Если правило Safe Page блокирует бота, в Blocked clicks сохраняются reason `bot` и полный исходный User-Agent.

В каждом flow также доступны два самостоятельных суточных правила:

- **Conversion cap (campaign)** считает все принятые строки истории выбранных статусов по всей кампании.
- **Conversion cap (flow)** считает только строки текущего flow.

Можно выбрать оператор `<`, `<=`, `=`, `!=`, `>=` или `>`, несколько статусов кампании и числовое значение. В счёт входят принятые платные повторы и upsell-записи. Границы дня определяются campaign timezone, а подсчёт всегда использует время строки конверсии и не зависит от режима атрибуции статистики. Если flow перестал соответствовать CAP-правилу, YellowTDS проверяет следующий flow, затем TrafficBack.

## Steps

В step можно задать:

- folders
- redirect URLs
- weights
- load type

Порядок steps меняется той же ручкой слева от номера шага. Redirect является завершающим действием, поэтому такой step закреплён последним и не перетаскивается.

## MVT лендинга

У каждой folder-записи есть собственная секция **MVT**. В HTML лендинга вставьте автоматически показанный placeholder, например `#TEST1#`, затем добавьте для TEST текстовые или HTML-значения. YellowTDS равномерно и независимо выбирает по одному Value для каждого активного TEST и выполняет доверенную строковую замену; одинаковый placeholder можно использовать в HTML несколько раз.

TEST нумеруются по порядку создания. Values получают коды A, B … Z, AA и далее. Сохранённые Values нельзя редактировать: их можно только архивировать и добавить новый Value в конец. Архивированный TEST или Value остаётся в конфигурации и сохраняет свой номер или код, поэтому нумерация никогда не откатывается.

![Настройка MVT у folder-записи](../assets/screenshots/campaign-settings-mvt.png)

Один `clickid + step` всегда использует одну и ту же комбинацию лендинга и MVT. Новый клик сначала ищет сохранённый выбор в текущей PHP-сессии. Если включён **Save user path**, запасной выбор также хранится в существующей cookie `saved_paths` пять дней. Direct Load при F5 или Back читает назначение достигнутого step и не выбирает комбинацию заново.

Новые назначения используют только активные TEST и Values. Уже назначенный архивированный Value продолжает рендериться для существующего click, session или Sticky path, пока MVT включён. При выключенном MVT placeholders не заменяются: YellowTDS не сканирует и не исправляет HTML автоматически.
